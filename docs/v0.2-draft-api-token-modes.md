# v0.2 草稿 API 与 Token 模式

## 决策

v0.2 增加微信公众号草稿箱创建能力，但文章上传仍然保持本地执行。

CLI 支持两种 token 模式：

```txt
本地 AppID/AppSecret -> 本地获取 token -> 本地上传图片 -> 本地创建草稿
中心 token 服务 -> 本地获得 token -> 本地上传图片 -> 本地创建草稿
```

v0.2 中，中心服务只是 token 提供方，不是文章发布代理。

## 当前实现

CLI 已实现：

- `draft <package-or-dir>`
- `--token-mode local|center`
- `--dry-run`
- 本地 AppID/AppSecret token provider
- 中心 token provider 合约
- 本地正文图片上传流程
- 本地封面上传流程
- 本地 `draft/add` 调用
- 可选 `--submit-preview`，输出最终提交 HTML 和草稿 payload
- 提交前正文转换：移除重复标题 H1 和顶部封面图
- 提交前正文转换：把代码块统一成浅色样式
- 提交前正文转换：清理可能在微信编辑器里变成空项目符号的列表空白
- 作者配置来自 `--author`、`WECHAT_MP_AUTHOR`、`WECHAT_PUBLISHER_AUTHOR` 或文章包元数据
- 默认请求原创字段，可用 `--no-original` 关闭
- `wechat-draft-report.json`

真实创建草稿仍然需要有效的公众号配置和 IP 白名单。

## 目标

- 把渲染后的 `article-package.json` 转成微信公众号草稿。
- 从本地文章包上传正文图片到微信。
- 从本地上传封面并使用返回的 `thumb_media_id`。
- 把 `content_html` 中的本地图片路径替换成微信图片 URL。
- 写入本地 `wechat-draft-report.json`。
- 默认不把文章 HTML、图片、封面和本地路径发送给中心服务。

## 非目标

- 默认不直接公开发表。
- 不做浏览器登录自动化。
- 不保存微信 Cookie 或 session。
- v0.2 不在中心侧渲染文章、上传图片或创建草稿。
- `AppSecret` 可以保存在用户本机私有配置文件中，但该文件必须被 git 忽略，不能进入包、报告、日志、示例或公开仓库。

## CLI 形态

```bash
wechat-publisher draft dist/article-package.json --token-mode local
wechat-publisher draft dist/article-package.json --token-mode center --account acct_xxx
```

第一个参数可以是 `article-package.json` 路径，也可以是包含 `article-package.json` 的输出目录。

常用参数：

```txt
--config <file>
--token-mode local|center
--app-id <id>
--app-secret <secret>
--account <account_id>
--author <name>
--original / --no-original
--dry-run
--submit-preview
--out <report_dir>
```

本地 token 模式：

```bash
wechat-publisher draft dist/article-package.json
```

默认配置文件：

```json
{
  "wechat": {
    "tokenMode": "local",
    "appId": "wx_your_app_id",
    "appSecret": "your_app_secret",
    "author": "作者名称",
    "original": true
  }
}
```

`wechat-publisher.config.json` 是本机私有配置，必须被 git 忽略。

中心 token 模式：

```bash
WECHAT_PUBLISHER_CENTER_URL=https://api.example.com \
WECHAT_PUBLISHER_CENTER_API_KEY=xxx \
wechat-publisher draft dist/article-package.json --token-mode center --account acct_xxx --author "作者名称"
```

## 运行流程

```txt
解析文章包
-> 校验文章包和素材
-> 从提交内容中移除重复顶部标题和封面图
-> 统一代码块样式，并清理微信编辑器不友好的列表空白
-> 从选定 token provider 获取 access_token
-> 上传正文图片到微信
-> 替换 HTML 中的图片 src
-> 上传封面为永久素材
-> 可选写入 wechat-submit.html 和 wechat-draft-payload.json
-> 调用微信 draft/add
-> 写入 wechat-draft-report.json
```

使用 `--dry-run --submit-preview` 时，CLI 不会调用微信。它仍然会写入转换后的提交 HTML，以及脱敏安全的草稿 payload，并使用 dry-run 封面 media 占位符。

## Token Provider

### 本地 Provider

输入：

- `wechat.appId`、`WECHAT_MP_APP_ID` 或 `--app-id`
- `wechat.appSecret`、`WECHAT_MP_APP_SECRET` 或 `--app-secret`

行为：

- 直接从微信获取 `access_token`。
- token 缓存在操作系统用户缓存目录下，不放在项目目录。
- 永远不打印 `AppSecret` 或 `access_token`。
- 保持 `wechat-publisher.config.json` 不进入 git。
- 当微信拒绝调用方 IP 时，明确失败原因。

### 中心 Provider

输入：

- `WECHAT_PUBLISHER_CENTER_URL`
- `WECHAT_PUBLISHER_CENTER_API_KEY`
- `--account <account_id>`

行为：

- 从中心服务请求短期 token。
- 请求包含账号身份和客户端版本。
- 默认不包含文章 HTML、图片文件、封面文件、本地路径或文章标题。
- 本地 CLI 使用返回的 token 直接调用微信。

建议接口：

```http
POST /v1/wechat/token
Authorization: Bearer <WECHAT_PUBLISHER_CENTER_API_KEY>
Content-Type: application/json
```

请求：

```json
{
  "account_id": "acct_xxx",
  "client": {
    "name": "wechat-publisher",
    "version": "0.2.0"
  }
}
```

响应：

```json
{
  "account_id": "acct_xxx",
  "access_token": "ACCESS_TOKEN",
  "expires_at": "2026-05-30T14:00:00+08:00",
  "token_type": "wechat_mp_access_token"
}
```

## 草稿报告

`wechat-draft-report.json` 写在文章包旁边，或写到 `--out` 指定目录。

```json
{
  "status": "success",
  "token_mode": "center",
  "account_id": "acct_xxx",
  "draft_media_id": "MEDIA_ID",
  "content_images": [
    {
      "asset_id": "asset_001",
      "local_path": "assets/image-001.png",
      "wechat_url": "https://mmbiz.qpic.cn/..."
    }
  ],
  "cover": {
    "local_path": "assets/cover.png",
    "thumb_media_id": "MEDIA_ID"
  },
  "original": {
    "requested": true,
    "original_article_type": 1,
    "creation_source_type": 1
  },
  "created_at": "2026-05-30T12:00:00+08:00",
  "warnings": [],
  "errors": []
}
```

启用 `--submit-preview` 时，报告还会记录快照文件：

```json
{
  "submit_preview": {
    "html_path": "/path/to/wechat-submit.html",
    "payload_path": "/path/to/wechat-draft-payload.json"
  }
}
```

## 安全规则

- `AppSecret` 和 `access_token` 不能写入报告、打印到日志、提交到仓库或包含在发布包中。
- `wechat-draft-payload.json` 不能包含 `access_token`、`AppSecret`、Cookie 或 session 数据。
- 本地私有配置可以包含 `AppSecret`，但必须被 git 忽略，并按机器本地状态处理。
- token 缓存必须放在项目目录之外。
- v0.2 中，中心模式不能接收文章内容。
- 如果以后增加中心侧发布，必须作为独立显式模式，不能静默改变当前行为。
- 默认动作只创建草稿。直接发表需要单独命令和显式确认。

## 验收标准

- `--dry-run` 在不调用微信的情况下，校验文章包结构、必要元数据、本地素材和所选 token 模式配置。
- `--dry-run --submit-preview` 在不调用微信的情况下，写入 `wechat-submit.html`、`wechat-draft-payload.json` 和 `wechat-draft-report.json`。
- 本地模式在配置有效 AppID/AppSecret 和 IP 白名单后，可以创建真实草稿。
- 中心模式可以使用中心服务返回的 token 创建真实草稿。
- 失败信息能明确区分：文章包校验、token 获取、IP 白名单、图片上传、封面上传或草稿创建。
